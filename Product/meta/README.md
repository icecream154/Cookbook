# 产品文档工程元规范（Product Specification Meta-Framework）

本目录（`meta/`）是一套**与具体业务领域完全无关、可跨项目直接复用的产品文档工程规范体系**。它不定义任何特定产品的功能或数据，而是专门规定：**一套高质量、可持续演进、零歧义交付的产品规格库（`spec/`）应当如何分层组织、如何编码命名、如何结构化行文、如何构建可交互微原型，以及如何随产品迭代持续演进**。

> **跨项目复用说明**：启动任何新软件产品项目时，可直接将本 `meta/` 目录原封不动拷贝至新仓库的 `Product/meta/` 下作为文档宪法，再在同级新建 `Product/spec/` 编写该产品的业务规格实例。

---

## 一、核心设计公理（Core Axioms）

本元规范体系建立在以下四条工程公理之上，旨在彻底根治传统单体长篇 PRD“难检索、易矛盾、改不动、读完即弃”的通病：

1. **活文档基线公理（Living Canonical Baseline）**
   产品规格库始终描述产品**当前最新生效的完整规格基线**，严禁按阶段堆砌“MVP PRD”、“二期补充 PRD”、“V2.1 变更说明”等碎片化快照。产品演进时直接在对应分层原地更新，历史差异交由 Git 版本控制系统追溯。
2. **正交分层与单一事实源公理（Orthogonal Single Source of Truth）**
   将产品规格按关注点拆解为职责正交的八个标准层（`01` ~ `08`）。每一类信息（如字段结构、枚举字典、计算公式、公共组件、单页排版、埋点属性）在全库**只允许在唯一归属层定义一次**，其他层一律通过锚点链接引用，严禁跨文档复制粘贴。
3. **结构化契约行文公理（Structured Contract over Prose）**
   禁止使用边界模糊的大段自然语言散文描述复杂逻辑。数据建模、条件分支（超过 2 个分支时强制使用决策矩阵表）、页面区块绑定、界面状态枚举与事件响应必须采用标准化的二维表格、状态机或流程图精确陈述。
4. **完全自包含公理（Zero-Context Self-Containment）**
   规格文档必须面向首次阅读的新协作者完全自解释。严禁在正式文档中残留会议讨论过程代号（如“采用方案 B”、“按昨天定的方式 C”）或未经注册解释的内部缩写黑话。
