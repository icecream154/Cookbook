# 01. 正交八层架构、模块职责红线与二级分包法则

本文档规定产品规格实例库（`spec/`）的**标准顶层目录结构、各层准入与越界禁令红线，以及当规模扩大时的二级子目录正交划分法则与具体文件概念释义**。

> **阅读说明**：本文档属于跨项目通用的元规范，文中所有“通用示例”均以常见的在线交易/预订系统（如商品、订单、结算）作为中性教学示意，不绑定任何特定业务项目。

---

## 1. 标准顶层目录拓扑

任意遵循本元规范的产品规格库（`spec/`），其顶层结构固定由 1 份导航总入口与 `01` ~ `08` 八个职责正交的业务规格层构成：

```text
spec/
├── README.md                        # 产品规格总导读（产品背景、命名空间速查表、全量文档索引、角色阅读路径）
├── 01-vision-and-scope.md           # 第 1 层：产品愿景、目标人群场景、功能版图与非目标边界、全局非功能约束
├── 02-domain-model/                 # 第 2 层：静态领域模型（业务术语定义、实体字段契约、全局标准枚举字典）
├── 03-business-rules/               # 第 3 层：全局动态业务规则库（跨领域计算、判定矩阵、过滤与降级兜底策略）
├── 04-ia-and-flows/                 # 第 4 层：信息架构与端到端流程（多端导航容器壳、跨页面业务流与状态同步）
├── 05-components-and-patterns/      # 第 5 层：公共业务组件与交互契约（跨页复用 UI 组件、全局通用交互状态机）
├── 06-pages/                        # 第 6 层：单页与子视图规格书（区块排版、字段绑定、页面状态枚举、交互事件表）
├── 07-metrics-and-tracking/         # 第 7 层：数据度量与埋点字典（北极星与转化漏斗公式、关键业务事件及属性契约）
└── 08-verification/                 # 第 8 层：验收与可交互微原型（结构化验收清单、单页状态画板、跨页动线微原型）
```

## 2. 八层职责准入边界与越界禁令红线（含正反判定示例）

为防止同一业务事实在多处重复抄写并随演进产生分歧，各层必须严格遵守以下**准入范围**与**越界禁令**：

| 层级 | 允许承载的信息（职责准入 + ✅ 正确示例） | 严禁写入的信息（越界禁令 + ❌ 错误反例） |
| :--- | :--- | :--- |
| **`01` 愿景与范围** | 痛点背景、一句话定位、目标人群场景、当前纳入的功能版图、明确排除的非目标边界（Non-Goals）、全局非功能约束。<br>✅ *示例：定义“支持多币种跨境结算（In-Scope），暂不自建跨境物流仓储（Non-Goal）”。* | 严禁展开具体数据库字段、算法公式或页面按钮位置。<br>❌ *反例：在 `01` 中写“订单表需包含 `currency_code` 字段，保留两位小数四舍五入”。* |
| **`02` 领域模型** | 业务专有术语标准定义、静态数据实体的字段名/类型/必填约束、全局标准枚举编码与展示文案。<br>✅ *示例：定义 `Order` 实体的结构字段，以及 `OrderStatus` 枚举含待支付/已支付/已取消。* | 严禁混入动态推荐/计价/超时流转等运行期规则，严禁规定 UI 控件形态。<br>❌ *反例：在字段说明里写“未支付超过 15 分钟自动关单，并在页面右上角标红字”（前者属 `03`，后者属 `06`）。* |
| **`03` 业务规则** | 横跨多个实体或页面的计算公式、布尔过滤条件、多分支决策矩阵、数据冲突裁决、空结果或异常时的业务降级兜底。<br>✅ *示例：定义“满减券与会员折扣叠加优先级矩阵，以及库存不足时的拆单兜底规则”。* | 严禁描述页面栅格排版、抽屉滑出方向或按钮摆位等界面布局细节。<br>❌ *反例：在规则文档中写“优惠金额用 16px 橙色加粗字体展示在提交按钮左侧”。* |
| **`04` 架构与流程** | 全站页面层级拓扑、不同屏幕断点下的外框导航壳、用户完成端到端任务的跨页跳转路径、跨页面状态变更的同步时机。<br>✅ *示例：绘制“购物车 → 确认订单 → 支付收银台 → 支付结果页”的流转及返回后购物车清空同步。* | 严禁在跨页流程图中塞入单页内部的细碎输入框格式校验，严禁抄写组件字段。<br>❌ *反例：在跨页流程图里画 5 个菱形分别校验“手机号是否 11 位、邮编是否纯数字”。* |
| **`05` 组件与交互** | 在 **`>= 2` 个独立页面/空间**中复用的复合业务组件及其场景变体、跨页面一致的通用交互状态机。<br>✅ *示例：定义在首页、搜索页、收藏页共用的“商品摘要卡片”及“未登录拦截后自动接续原操作”机制。* | 严禁收录仅在某一个页面单独出现的一次性局部区块。<br>❌ *反例：把只在“个人设置页”出现一次的“关于我们版本号展示块”放进公共组件层。* |
| **`06` 页面规格** | 单个页面或高复杂度子视图的出入口与权限、多端区块排列、组件组装与实体字段绑定、该页面完整状态枚举、交互事件映射表。<br>✅ *示例：声明“区块 B 挂载 `COMP-ProductCard`（搜索变体），点击加购触发 `RULE-CART-01` 并上报 `EVT-04`”。* | **三不抄铁律**：严禁在单页文档平铺抄写枚举值全集（须链接 `02`）、严禁重写计算公式（须链接 `03`）、严禁重复描述公共组件与通用交互细节（须链接 `05`）。 |
| **`07` 指标与埋点** | 北极星指标定义、核心业务漏斗转化率公式、支撑指标计算的关键业务事件触发时机与必传业务属性。<br>✅ *示例：定义“结算转化率公式”及底层 `checkout_submitted` 事件的必传业务属性契约。* | 严禁堆砌无任何指标消费的无效曝光埋点，严禁绑定特定第三方埋点 SDK 代码。<br>❌ *反例：在规格中写入 `window.sensors.track(...)` 具体前端调用代码。* |
| **`08` 验收与原型** | `Given-When-Then` 结构化验收用例集、低保真单页多状态交互画板 HTML、跨页状态传递微原型 HTML。<br>✅ *示例：提供顶栏带 `[S1 正常态] [S2 空购物车] [S3 库存失效]` 一键切换按钮的线框 HTML 画板。* | 严禁写成大而全的单体生产级前端工程，严禁添加 `01`~`06` 未定义的野生功能，严禁提前介入高保真品牌配色与视觉精修。 |

## 3. 二级子目录与多文件正交拆分法则（含概念详解与示例）

当某一层的规格内容较多、单文件承载会导致阅读与维护困难时，严禁随意切分，必须遵循该层专属的**正交分类轴**。下表先给出全局速览，随后在 `3.1` ~ `3.7` 逐层解释每个具体文件概念与拆分实例：

| 层级 | 强制二级分类轴（按什么维度拆） | 标准目录与文件构成 |
| :--- | :--- | :--- |
| **`01` 愿景与范围** | 不拆分（全局宏观统领） | 固定单文件 `01-vision-and-scope.md` |
| **`02` 领域模型** | **按限界上下文（业务数据归属子域）拆子目录** | 每个子域一个文件夹，内部固定拆为 `terms.md`、`entities.md`、`enums.md` |
| **`03` 业务规则** | **按核心业务决策能力簇（Business Capability）拆文件** | 按内聚决策主题拆分为若干 `<capability>.md` 专题规则文件 |
| **`04` 架构与流程** | **容器壳独立 + 流程按用户价值旅程阶段拆文件** | `ia-and-shell.md` + `flows/<journey-stage>.md` |
| **`05` 组件与交互** | **按“可视复用 UI 组件”与“无形跨页交互契约”二分** | `shared-components.md` + `interaction-patterns.md` |
| **`06` 页面规格** | **按信息架构功能空间（IA Space）拆子目录，主从视图拆小文件** | `<space>/<main-page>.md` + `<space>/<complex-drawer-or-modal>.md` |
| **`07` 指标与埋点** | **按“上层业务度量公式”与“底层采集事件字典”二分** | `metrics-funnel.md` + `event-dictionary.md` |
| **`08` 验收与原型** | **验收清单独立 + 原型按“共享底座 / 单页画板 / 跨页沙盒”三分** | `acceptance-criteria.md` + `prototypes/{index.html, shared/, pages/, flows/}` |

### 3.1 `02-domain-model/`：什么是“限界上下文子域”与三类标准文件？

- **为什么先按“限界上下文（子域）”建文件夹？**
  中大型产品往往包含数十个业务对象，如果全塞进同一个文件，阅读者根本分不清主次。按业务数据的自然所有权与生命周期内聚性划分文件夹（*例如电商系统可划分为 `member/` 会员账户域、`catalog/` 商品目录域、`order/` 交易订单域*），能让研发直接按子域对应微服务或数据库模块。
- **每个子域内部的 3 份标准文件分别写什么？**
  1. **`terms.md`（业务术语表）**：专门消除团队沟通歧义的“词典”，定义那些在日常口语中容易理解不一致的专有概念。
     - *通用示例*：在 `catalog/terms.md` 中严格定义什么叫“**可售库存**（物理在库总数减去已下单未支付锁定量及残次冻结量）”，防止产品、运营、开发各自按不同口径理解“库存”。
  2. **`entities.md`（静态实体结构契约）**：定义系统中需要持久化存储或跨前后端传输的“名词对象”由哪些字段组成、什么类型、是否必填（对应数据库的表结构或 API 的核心 Model）。
     - *通用示例*：在 `order/entities.md` 中定义订单实体 `DOM-ORD-Order`，声明其包含 `orderId (String, 必填)`、`buyerId (String, 必填)`、`payableAmount (Int, 分, 必填)`、`status (关联枚举 OrderStatus)` 等字段。
  3. **`enums.md`（全局标准枚举字典）**：定义实体字段或筛选条件中所有“取值封闭、全站统一命名”的选项列表（含程序内部编码 `Code` 与界面展示文案 `Label`）。
     - *通用示例*：在 `order/enums.md` 中定义 `ENUM-ORD-OrderStatus`，封闭列举 `UNPAID（待付款）`、`PAID（待发货）`、`SHIPPED（已发货）`、`COMPLETED（已完成）`，全站所有页面和规则涉及订单状态时一律引用此处，杜绝某页叫“未付款”、另一页叫“待支付”。

### 3.2 `03-business-rules/`：为什么按“业务决策能力簇”拆文件，而不按静态实体拆？

- **核心原因**：真实的业务规则几乎都是**跨多个静态数据域联合读取**的。*例如“订单结算凑单计价规则”，既要读 `member/` 域的会员等级折扣，又要读 `catalog/` 域的商品类目满减门槛，还要读 `order/` 域的应付总额*——如果强行把规则塞进某一个静态实体目录，就会导致严重的归属冲突。
- **正确拆法**：按系统需要做出的**核心业务决策能力**建立专题文件。
  - *通用示例*：在电商系统中，可将 `03-business-rules/` 拆分为 `pricing-and-promotion.md`（计价与优惠叠加规则簇）、`inventory-allocation.md`（库存锁定与拆单规则簇）、`refund-eligibility.md`（售后退换货准入判定规则簇）。

### 3.3 `04-ia-and-flows/`：什么是“全局拓扑与多端导航壳”以及“按用户旅程拆流程”？

本目录拆分为 1 份架构壳文档与 1 个跨页流程文件夹：
1. **`ia-and-shell.md`（信息架构全局拓扑与多端导航容器壳）**：承载两项全局骨架定义：
   - **全局页面拓扑（IA Topology）**：一张俯瞰全站的“地图”，展示整个应用一共由哪几个一级导航模块、二级详情页、全局公共弹窗构成，以及它们之间的父子归属层级。
   - **多端导航容器壳（Responsive App Shell）**：包裹在具体页面内容外围的“公共外框与导航栏”在不同终端屏幕宽度下的自适应变形规范。
     - *通用示例*：规定同一套系统在**手机竖屏**（`<768px`）下采用“底部固定四栏 Tab 导航 + 底部上滑半屏抽屉”；在**平板横屏**（`768~1023px`）下变形为“左侧窄图标导航轨 + 左列表右详情分栏”；在**桌面宽屏**（`>=1024px`）下变形为“左侧完整菜单栏 + 右侧多栏常驻工作台 + 居中模态窗”。把外框在 `04` 定义清楚后，`06` 的每个单页就不需要重复画导航栏了。
2. **`flows/<stage>.md`（按用户价值旅程阶段拆分的端到端流程）**：
   - 将跨多个页面才能走完的完整用户任务流，按用户使用产品的**先后价值阶段**分文件管理。
   - *通用示例*：拆分为 `01-onboarding-and-auth.md`（冷启动引导与注册登录阶段）、`02-browsing-and-search.md`（商品发现与筛选加购阶段）、`03-checkout-and-fulfillment.md`（下单支付与履约签收阶段）。

### 3.4 `05-components-and-patterns/`：“有形复合组件”与“无形跨页交互契约”有什么区别？

凡在 **`>= 2` 个页面**重复出现的设计资产全部收口至本层，并按“看得见的 UI 零件”与“看不见的交互机制”一分为二：

1. **`shared-components.md`（有形跨页复用业务组件 `COMP-*`）**
   - **概念解释**：指界面上**看得见、有明确视觉边界、内部组合了多个字段与按钮**的复合业务 UI 模块，且在不同页面挂载时往往存在细微的“场景变体”。
   - *通用示例*：
     - **商品摘要卡片 `COMP-ProductCard`**：在“首页推荐流”、“搜索结果页”、“我的收藏页”三处复用，主体都是封面图+标题+价格，但首页变体额外展示“推荐理由标签”，收藏页变体额外展示“取消收藏按钮”——在此处用一张变体矩阵表统一定义。
     - **数量步进调节器 `COMP-QuantityStepper`**：在购物车行与商详页规格区复用的 `[- 数量 +]` 控件（含最小起购量置灰、库存上限拦截反馈）。
2. **`interaction-patterns.md`（无形跨页交互行为契约 `PAT-*`）**
   - **概念解释**：它不是某一个固定摆放位置的 UI 卡片，而是贯穿全站多个页面的**通用交互行为状态机、拦截恢复逻辑或全局反馈规范**。
   - *通用示例*：
     - **受限动作鉴权拦截与自动接续 `PAT-AuthResume`**：规定全站任何允许游客浏览的页面，当游客点击“收藏”、“加购”或“关注”时，系统先挂起该动作并弹出登录框；**一旦用户登录成功，系统必须自动替用户把刚才点击的“收藏/加购”执行完毕**，而不是只关掉登录框让用户再点一遍。
     - **破坏性移除延迟撤销条 `PAT-UndoSnackbar`**：规定用户在列表执行移除操作时，不弹烦人的二次确认框，而是直接从列表隐去并在底部浮出 4 秒“已移除 · [撤销]”提示条，倒计时内点撤销即可无损恢复。
     - **全局视图异常四态契约 `PAT-ViewStates`**：统一规定全站所有页面在“首屏加载中（骨架屏）”、“列表零数据（空状态引导）”、“网络请求失败（局部重试块）”、“轻量操作成功（顶部/底部轻提示）”时的标准交互行为。

### 3.5 `06-pages/`：如何按“功能空间”分文件夹，并将主页面与复杂子视图拆开？

- **按 IA 功能空间分文件夹**：与全站的一级导航模块及核心跨模块空间一一对应建子目录（*例如：`home/`、`search/`、`cart/`、`order-detail/`、`profile/`*）。
- **主页面与高复杂度专属子视图平级拆分**：如果某个主页面挂载了一个字段极多、内部状态复杂的专属抽屉、侧边筛选面板或全屏专注视图，严禁把几百行弹窗细节硬塞进主页面文档里，必须在同一空间文件夹下将其拆成独立的平级规格文件。
  - *通用示例*：在 `search/` 空间目录下，拆分为 `search-result-page.md`（搜索结果主页面 `PAGE-SRCH-01`）与 `advanced-filter-drawer.md`（多维高级筛选抽屉面板 `PAGE-SRCH-02`）两份精炼的五段式文档，互相通过链接跳转。

### 3.6 `07-metrics-and-tracking/`：为什么要拆成 `metrics-funnel.md` 与 `event-dictionary.md`？

为了根治业务团队“拍脑袋提一堆埋点却没人看”或数据团队“想算转化率却发现漏埋了关键属性”的脱节问题，本层按“**上层怎么算指标**”与“**底层怎么采事件**”拆为上下咬合的两份文件：

1. **`metrics-funnel.md`（业务指标体系与漏斗公式 `MET-*`）**
   - **定位**：面向产品经理、业务方与数据分析师，定义衡量产品健康度的**北极星指标**与各核心模块的**漏斗转化率数学公式**（分子、分母必须精确写成底层事件编号的运算组合）。
   - *通用示例*：定义 `MET-02 搜索加购转化率 = 统计周期内触发 EVT-05 (add_to_cart 且 source='search') 的去重用户数 ÷ 触发 EVT-03 (search_executed) 的去重用户数`。
2. **`event-dictionary.md`（关键业务事件采集字典 `EVT-*`）**
   - **定位**：面向前后端研发与测试工程师，逐一定性定量地声明支撑上述公式所需的每一个**埋点事件英文名、在哪张页面/组件什么瞬间触发、必须携带哪些业务属性及数据类型**。
   - *通用示例*：定义 `EVT-03`（事件名 `search_executed`），在搜索结果页 `PAGE-SRCH-01` 发起检索返回响应时触发，必传属性：`query_text (String)`、`filter_count (Int)`、`result_total (Int)`，并注明该事件服务于指标 `MET-02`。

### 3.7 `08-verification/`：验收清单与 `prototypes/` 下的四类目录分别承担什么职责？

本层负责把静态文字规格变成“可逐条打勾测试的准出底线”和“无需写后端代码即可在浏览器点击体验的交互原型”，内部固定拆分为以下 4 个部分：

1. **`acceptance-criteria.md`（端到端结构化验收清单 `AC-*`）**
   - **职责**：将核心业务流程及 `03` 中所有容易漏测的边界条件、空数据兜底转化为确定性的 `前置条件 (Given) → 触发操作 (When) → 预期结果 (Then)` 验收表，供研发提测前自检、QA 验收时逐条勾选。
   - *通用示例*：`Given` 用户账户有 1 张满 100 减 20 券且购物车商品合计 105 元 → `When` 在结算页取消勾选其中 10 元商品使合计降至 95 元 → `Then` 系统自动取消该优惠券勾选，实付金额更新为 95 元并提示“还差 5 元可用券”。
2. **`prototypes/index.html` 与 `prototypes/shared/`（导航总控台与统一低保真底座）**
   - **`index.html`**：在浏览器打开微原型的总目录入口页，卡片化列出下方所有单页状态画板与跨页动线沙盒，并提供跳回对应 Markdown 规格书的双向链接。
   - **`shared/`**：内含 `wireframe.css`（中性灰阶线框样式库，克制视觉干扰，聚焦布局结构）与 `mock-data.js`（严格按照 `02` 实体结构编写的一份共用模拟业务数据集，确保所有原型展示的商品/用户数据前后一致）。
3. **`prototypes/pages/*.html`（单页多状态交互画板 `PROTO-PAGE-*`）**
   - **职责**：每个功能空间对应一个独立的 HTML 文件，用来 100% 穷举展示该空间页面在各种正常与极端情况下的界面形态。
   - **核心交互特征**：画板顶部固定挂载一条**测试工作台控制栏**，提供两组一键切换开关——① **页面状态切换器**（与 `06` 页面规格第 4 节的状态枚举严格同名，例如点一下 `[S1 正常态]`、`[S2 游客态]`、`[S3 搜索零结果]`、`[S4 网络异常]`，画布无需任何前置铺垫立刻切换成对应界面）；② **视口宽度切换器**（一键切换手机 `390px` / 平板 `834px` / 桌面 `1280px` 检视响应式布局变化）。
4. **`prototypes/flows/*.html`（跨页状态传递沙盒 `PROTO-FLOW-*`）**
   - **职责**：单页画板擅长看“某一个页面的所有切面状态”，但看不出“在 A 页面改了数据或触发拦截，跳到 B 页面再回来时状态怎么衔接”。`flows/` 专门针对全站最关键的 2~3 条跨页面动态衔接链路建立轻量级交互沙盒。
   - *通用示例*：单独做一个 `flow-guest-checkout-resume.html` 沙盒，专门让评审者亲手点击体验“未登录游客在商详页点立即购买 → 弹出登录抽屉并检测到账号有历史默认地址 → 登录成功后无需重回商详页，直接带着刚选的商品规格与默认地址进入确认订单页”的丝滑跨页状态流转。
