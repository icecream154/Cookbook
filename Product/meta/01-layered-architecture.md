# 01. 正交八层架构、模块职责红线与二级分包法则

本文档规定产品规格实例库（`spec/`）的**标准顶层目录结构、各层准入与越界禁令红线，以及当规模扩大时的二级子目录正交划分法则**。

---

## 1. 标准顶层目录拓扑

任意遵循本元规范的产品规格库（`spec/`），其顶层结构固定由 1 份导航总入口与 `01` ~ `08` 八个职责正交的业务规格层构成：

```text
spec/
├── README.md                        # 产品规格总导读（产品背景、命名空间速查表、全量文档索引、角色阅读路径）
├── 01-vision-and-scope.md           # 第 1 层：产品愿景、目标人群场景、功能版图与非目标边界、全局非功能约束
├── 02-domain-model/                 # 第 2 层：静态领域模型（业务术语定义、实体字段契约、全局标准枚举字典）
├── 03-business-rules/               # 第 3 层：全局动态业务规则库（跨领域计算、判定矩阵、过滤与降级兜底策略）
├── 04-ia-and-flows/                 # 第 4 层：信息架构与端到端流程（多端导航容器壳、跨页面业务流与状态同步）
├── 05-components-and-patterns/      # 第 5 层：公共业务组件与交互契约（跨页复用 UI 组件、全局通用交互状态机）
├── 06-pages/                        # 第 6 层：单页与子视图规格书（区块排版、字段绑定、页面状态枚举、交互事件表）
├── 07-metrics-and-tracking/         # 第 7 层：数据度量与埋点字典（北极星与转化漏斗公式、关键业务事件及属性契约）
└── 08-verification/                 # 第 8 层：验收与可交互微原型（结构化验收清单、单页状态画板、跨页动线微原型）
```

---

## 2. 八层职责准入边界与越界禁令红线

为防止同一业务事实在多处重复抄写并随演进产生分歧，各层必须严格遵守以下**准入范围**与**越界禁令**：

| 层级 | 允许承载的信息（职责准入） | 严禁写入的信息（越界禁令） |
| :--- | :--- | :--- |
| **`01` 愿景与范围** | 核心痛点背景、一句话产品定位、目标人群与典型使用场景、当前纳入的功能版图、当前明确排除的非目标边界（Non-Goals）、全局非功能体验约束 | 严禁展开具体数据表字段、严禁编写算法计算细则、严禁描述具体页面按钮位置 |
| **`02` 领域模型** | 业务专有术语标准定义、静态数据实体的字段名/类型/必填约束、全局标准枚举编码与展示文案 | 严禁混入动态推荐/检索/折算等运行期规则、严禁规定 UI 控件形态或交互提示文案 |
| **`03` 业务规则** | 横跨多个实体或页面的计算公式、布尔过滤条件、多分支决策矩阵、冲突裁决逻辑、无结果或异常时的业务降级兜底（Fallback） | 严禁描述页面栅格排版、弹窗圆角阴影或按钮摆位等视觉布局细节 |
| **`04` 架构与流程** | 全站页面层级拓扑、不同终端断点下的导航容器壳、用户完成端到端任务的跨页跳转路径、跨页面状态变更的同步时机 | 严禁在流程图中塞入单页内部细碎表单项校验、严禁重复抄写公共组件内部字段 |
| **`05` 组件与交互** | 在 **`>= 2` 个独立页面/空间**中复用的复合业务组件及其场景变体、跨页面一致的通用交互状态机（如鉴权拦截恢复、撤销保护、统一四态反馈） | 严禁收录仅在单一页面使用的一次性私有局部模块 |
| **`06` 页面规格** | 单个页面或高复杂度子视图的出入口与权限、多端区块排列、组件组装与实体字段绑定、该页面的完整状态枚举、用户动作到规则/跳转/埋点的映射表 | **三不抄铁律**：严禁抄写枚举值全集（须链接至 `02`）、严禁重写业务计算公式（须链接至 `03`）、严禁重复描述公共组件与通用交互细节（须链接至 `05`） |
| **`07` 指标与埋点** | 北极星指标定义、核心业务漏斗转化率公式、支撑指标计算的关键业务事件触发时机与必传业务属性 | 严禁堆砌无任何指标消费的细碎曝光埋点、严禁耦合特定第三方埋点 SDK 的代码实现 |
| **`08` 验收与原型** | `Given-When-Then` 结构化验收用例集、低保真单页多状态交互画板 HTML、跨页状态传递微原型 HTML | 严禁写成大而全的单体生产级前端工程、严禁在原型中私自添加 `01`~`06` 未定义的野生功能、严禁混入高保真品牌配色与视觉精修决策 |

## 3. 二级子目录与多文件正交拆分法则

当某一层的规格内容较多、单文件承载会导致阅读与维护困难时，严禁随意按个人习惯切分，必须遵循该层专属的**正交分类轴**进行二级分包：

| 层级 | 强制二级分类轴（按什么维度拆） | 目录与文件组织标准 |
| :--- | :--- | :--- |
| **`01` 愿景与范围** | 不拆分（全局宏观统领） | 固定单文件 `01-vision-and-scope.md` |
| **`02` 领域模型** | **按限界上下文（业务数据归属子域）拆子目录** | 每个业务子域建一个独立文件夹（如 `<subdomain>/`）；子域内部固定按信息性质拆为 3 份标准文件：`terms.md`（术语）、`entities.md`（实体）、`enums.md`（枚举） |
| **`03` 业务规则** | **按核心业务决策能力簇（Business Capability）拆文件** | 因业务规则常同时读取多个数据子域，**严禁强行按静态数据表拆分**，而应按“系统执行的一组内聚决策能力”拆分为若干专题 `.md` 文件 |
| **`04` 架构与流程** | **容器壳独立 + 流程按用户价值旅程阶段拆文件** | 顶层放置 `ia-and-shell.md` 定义全局拓扑与多端导航壳；跨页流程统一收入 `flows/` 子目录，按用户使用生命周期阶段（如引导认证、核心作业、检索沉淀等）拆文件 |
| **`05` 组件与交互** | **按“可视复用 UI 组件”与“跨页交互行为契约”二分** | 固定拆分为 `shared-components.md`（有形复合控件）与 `interaction-patterns.md`（无形跨页交互机制与反馈契约） |
| **`06` 页面规格** | **按信息架构功能空间（IA Functional Space）拆子目录** | 对应一级导航模块及独立跨模块公共流划分文件夹；每个空间内，**宿主主页面**与**高复杂度专属抽屉/弹窗/全屏子视图**拆为平级独立小文件（避免单页文档过长） |
| **`07` 指标与埋点** | **按“上层业务度量公式”与“底层采集事件字典”二分** | 固定拆分为 `metrics-funnel.md` 与 `event-dictionary.md` |
| **`08` 验收与原型** | **验收清单独立 + 原型按“共享底座 / 单页画板 / 跨页动线”三分** | 顶层放 `acceptance-criteria.md`；`prototypes/` 下设 `index.html` 总控台、`shared/`（共用低保真样式与模拟数据）、`pages/`（与 `06` 功能空间对应的多状态画板）、`flows/`（跨页状态传递沙盒） |

---

## 4. 目录索引注册表（`_index.md`）强制公约

凡包含多个规格文件的目录（如 `02-domain-model/`、`03-business-rules/`、`04-ia-and-flows/flows/`、`05-components-and-patterns/`、`06-pages/`），其根部**必须提供 `_index.md` 文件**，且至少包含两部分内容：
1. **本层拆分依据说明**：向读者交代本目录采用了哪几个子域/能力簇/功能空间，以及各自的管辖边界；
2. **本层全量 ID 注册导航表**：汇总列出本层所有规格条目的唯一 ID、标准名称及跳转链接，作为下游引用检索的总目录。
