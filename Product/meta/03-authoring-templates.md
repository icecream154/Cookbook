# 03. 各层文档结构化陈述模板与行文规范

本文档定义 `01` ~ `07` 各层规格文档的**行文排版基本法**与**强制性结构模板（必填章节与表格列契约）**，消除不同编写者文风不一或遗漏关键契约的问题。

---

## 1. 全局行文与 Markdown 排版基本法

1. **表格与矩阵优先，禁止散文砌墙**：凡涉及实体结构、枚举取值、超过 2 个条件组合的分支规则、多端布局差异、页面状态穷举、事件映射，一律使用结构化 Markdown 表格表达；连续纯文本段落不得超过 4 行。
2. **中英文混排加粗安全规范（CommonMark 兼容）**：在标准 CommonMark 解析器中，闭合的 `**` 若内侧紧邻标点（如 `）`、`”`、`」`）且外侧紧邻中文字符而无空格或标点，会导致加粗解析失效。编写时统一**将括号或引号置于 `**` 外侧**（正确示例：`支持**移动端**（<768px）`、按“**可视组件**”拆分；禁止示例：`支持**移动端（<768px）**自适应`）。
3. **Mermaid 图表语法安全规范**：节点标签凡包含括号 `()`、斜杠 `/`、冒号 `:` 或星号 `*`，必须使用英文双引号包裹（如 `N1["PAGE-XX-01 页面名 (弹窗)"]`），且严禁在节点标签内使用原始 HTML 标签。

---

## 2. 各层标准结构与必填列契约

### <a id="tpl-vision"></a>2.1 `01-vision-and-scope.md`（愿景、场景与范围）标准结构
固定由以下 4 节组成：
1. **产品背景与核心价值主张**：痛点清单 + 一句话产品定位。
2. **目标人群与核心场景表（`SCN-*`）**：必填列 `场景 ID | 目标人群画像 | 触发情境 (When & Where) | 核心诉求 (Goal) | 现存痛点阻碍 (Pain)`。
3. **产品功能版图与范围边界（`FEAT-*`）**：
   - `3.1 当前纳入的功能版图（In-Scope）`：必填列 `功能 ID | 功能名称 | 归属业务模块 | 支撑场景 (链接 SCN-*) | 核心能力边界定义 | 下游核心映射`。
   - `3.2 当前产品非目标边界（Non-Goals / Out-of-Scope）`：明确列出暂不涉足的相邻领域及演进准入条件。
4. **全局非功能体验约束表（`NFR-*`）**：必填列 `约束 ID | 约束维度 | 可量化或可验证的规格要求`。

---

### <a id="tpl-domain"></a>2.2 `02-domain-model/<subdomain>/`（静态领域模型）标准结构
每个业务子域目录下拆分为以下 3 份标准文档：
- **`terms.md`（业务术语表 `TERM-*`）**：必填列 `术语 ID | 标准中文名 | 英文标识 | 严格业务定义 | 易混淆反例说明`。
- **`entities.md`（静态实体契约 `DOM-*`）**：每个实体包含一句聚合根/归属说明及字段契约表，必填列：
  `字段标识 (camelCase) | 中文名称 | 数据类型 | 必填 | 取值约束 / 关联实体或枚举 (链接) | 业务语义说明`
- **`enums.md`（全局标准枚举字典 `ENUM-*`）**：每个枚举包含一张封闭取值表，必填列：
  `枚举编码 (Code) | 标准展示文案 (Label) | 排序或计算权重 | 业务判定语义说明`

---

### <a id="tpl-rule"></a>2.3 `03-business-rules/<capability>.md`（全局业务规则）五要素卡片模板
每条 `RULE-*` 规则必须严格按以下**固定五要素结构**编写，缺一不可：
1. **触发时机与适用范围**：在什么业务动作或系统事件下调用本规则。
2. **输入依赖契约**：显式列出并链接本规则读取的所有 `DOM-*` 字段与 `ENUM-*` 字典。
3. **核心判定矩阵 / 计算公式**：使用精确数学表达式、优先级列表或多维决策矩阵表给出确定性输出。
4. **边界与降级兜底（Fallback）**：明确输入缺失、零命中、极端数值或数据冲突时的保底行为（严禁留白）。
5. **下游消费索引**：列出调用本规则的流程 `FLOW-*` 与页面 `PAGE-*` 链接，便于变更影响评估。

---

### <a id="tpl-flow"></a>2.4 `04-ia-and-flows/`（信息架构与端到端流程）标准结构
- **`ia-and-shell.md`**：
  1. 全站页面层级拓扑图（Mermaid `flowchart`）；
  2. 多端响应式容器壳规格表（`SHELL-*`）：必填列 `容器壳 ID | 视口断点范围 | 一级导航形态 | 内容区栅格与分栏规则 | 抽屉/浮层适配变形规则`。
- **`flows/<stage>.md`**：每条 `FLOW-*` 必须包含：
  1. **前置条件与触发入口**；
  2. **端到端流程图（Mermaid `flowchart`）**：页面节点必须标注 `[PAGE-*]`，判断菱形必须标注 `[RULE-*]` 或 `[PAT-*]`；
  3. **异常分支与跨页状态同步说明**：写明离开当前页后对其他页面的数据刷新影响。

---

### <a id="tpl-comp"></a>2.5 `05-components-and-patterns/`（公共组件与交互契约）标准结构
- **`shared-components.md`（`COMP-*`）**：每个组件必须定义：
  1. **复用页面范围**（列出 `>= 2` 个引用页）；
  2. **数据输入属性契约**（链接至 `DOM-*` / `ENUM-*`）；
  3. **场景变体矩阵表**：必填列 `变体名称 | 挂载页面 (PAGE-*) | 差异化展示元素 | 专属局部操作`；
  4. **组件内聚交互与事件透出**。
- **`interaction-patterns.md`（`PAT-*`）**：每个全局交互模式必须定义：
  1. **适用触发场景与设计意图**；
  2. **状态流转图（Mermaid `stateDiagram-v2`）或时序规约**；
  3. **超时、取消或失败时的边界处理**。

---

### <a id="tpl-page"></a>2.6 `06-pages/<space>/<view>.md`（单页与子视图规格）固定五段式模板
任何 `PAGE-*` 文档必须且仅能由以下 **5 个标准小节**构成，保持高度简洁与正交：
1. **页面元信息表**：包含 `页面 ID`、`视图载体形态`（一级主页 / 二级页 / 抽屉 / 模态窗 / 全屏覆盖层）、`访问权限要求`、`上游进入路径`、`下游跳转出口`、`关联可交互画板原型链接`。
2. **多端响应式区块布局表**：链接 `SHELL-*`，说明各视口断点下的分栏、吸顶或折叠差异。
3. **区块组装与数据绑定表**：必填列 `区块编号 | 区块名称 | 选用公共组件 (COMP-*) 或原子控件 | 绑定实体字段 (链接 DOM-*/ENUM-*) | 显隐与渲染条件`。
4. **页面级状态枚举表**：穷举该视图全部互斥或叠加状态，必填列 `状态编码 (S1/S2/...) | 状态名称 | 触发条件 | 界面视觉与文案变化特征 | 允许的恢复动作`（**注：状态编码须与 `08` 画板原型状态按钮 1:1 严格一致**）。
5. **交互事件映射表**：必填列 `用户操作 (When) | 前置拦截/交互模式 (链接 PAT-*) | 调用业务规则 (链接 RULE-*) | 界面反馈或路由跳转 (Then) | 触发埋点 (链接 EVT-*)`。

---

### <a id="tpl-metric"></a>2.7 `07-metrics-and-tracking/`（核心指标与事件字典）标准结构
- **`metrics-funnel.md`（`MET-*`）**：
  1. 北极星指标定义表（`MET-NSM`）：统计周期、基于 `EVT-*` 的精确去重计算公式、业务指导意义；
  2. 核心业务漏斗与质量指标表（`MET-01`...）：必填列 `指标 ID | 指标名称 | 精确分子/分母计算公式 (引用 EVT-*) | 健康关注方向与业务诊断价值`。
- **`event-dictionary.md`（`EVT-*`）**：
  必填列 `事件 ID | 事件英文名 (snake_case) | 触发载体 (链接 PAGE-*/COMP-*) | 精确触发时机 | 必传业务属性及类型契约 | 消费该事件的指标 (链接 MET-*)`。
