# 04. 结构化验收标准与双轨可交互微原型规范

本文档规定 `08-verification/` 层中**端到端验收用例集**（`AC-*`）与**可交互 HTML 微原型**（`PROTO-*`）的架构准则、粒度边界与实现示范。

---

## 1. 结构化验收标准（`acceptance-criteria.md`）编写规范与示例

验收标准是连接产品规格与研发提测自检、QA 准出测试的契约底线：
1. **组织与编号**：按核心业务能力模块分节，每条用例分配唯一编号 `AC-<CAP>-<NN>`。
2. **最低覆盖率红线**：
   - 每条核心端到端流程（`FLOW-*`）至少有 1 条正向闭环验收用例；
   - 每条全局业务规则（`RULE-*`）的**临界数值边界**与**异常/空结果降级兜底（Fallback）分支**必须有独立验收用例覆盖；
   - 所有跨页面状态同步点（如 A 页改设置影响 B 页、未登录拦截后自动接续）必须有专门验收用例覆盖。
3. **标准表格模板与通用示例**：
   ```markdown
   | 验收 ID | 关联规则 / 页面（附语义短名） | 前置条件 (Given) | 触发动作 (When) | 预期确定性结果 (Then) |
   | :--- | :--- | :--- | :--- | :--- |
   | <a id="ac-pric-01"></a>**AC-PRIC-01** | [RULE-PRIC-01 满减与会员折叠加计价](../03-business-rules/pricing.md#rule-pric-01)<br>[PAGE-CHK-01 确认订单主页](../06-pages/checkout/checkout-main.md#page-chk-01) | 买家持有满 100 减 100 无门槛抵扣券，选购单价 60 元包邮商品 | 进入 `[PAGE-CHK-01 确认订单页]` 勾选该抵扣券 | 实付金额按保底规则显示为 `0.01` 元（严禁出现 `0` 元或负数金额） |
   ```

---

## 2. 为什么严禁制作“大而全的单体可交互原型”？

在产品规格阶段，把整个应用写成单个包罗万象的 HTML/JS 单页应用（Monolithic Prototype）存在三大弊病：
1. **边缘状态极难检视**：评审者或 UI 设计师想看某个极端异常态（如“搜索零结果放宽提示”、“老账号数据合并冲突弹窗”或“弱网加载失败态”），不得不手动前置点击十余步去凑条件，导致大量边缘状态在评审与视觉出图时被漏掉。
2. **伪逻辑与文档脱节**：单体原型为了跑通全局数据，往往在前端脚本里硬编码大量临时状态逻辑，极易与 `03-business-rules/` 的正式规则产生分歧。
3. **局部改动牵连全局**：修改一个弹窗字段可能把整套单体原型的路由搞崩，维护成本极高。

因此，本元规范强制采用“**单页多状态交互画板 + 跨页状态传递微原型**”**双轨解耦架构**。

## 3. 双轨可交互 HTML 微原型架构与界面示范

### 3.1 标准目录组织
```text
08-verification/prototypes/
├── index.html                       # 微原型导航总控台（卡片化汇总全部画板与沙盒，双向链接 Markdown 规格书）
├── shared/
│   ├── wireframe.css                # 跨原型共用的中性灰阶低保真线框样式与多端视口容器壳样式
│   └── mock-data.js                 # 与 02 领域模型对齐的标准模拟数据集及核心纯函数演示器
├── pages/                           # 【轨道一】按 06 功能空间划分的单页多状态交互画板（PROTO-PAGE-*）
│   └── <space-name>.html
└── flows/                           # 【轨道二】聚焦关键跨页数据流转与拦截同步的微原型（PROTO-FLOW-*）
    └── <flow-name>.html
```

### 3.2 低保真视觉克制原则（Wireframe Fidelity Discipline）
产品规格中的 HTML 原型旨在验证**信息层级、区块组装、多端响应式变形、状态完备性与交互闭环**，严禁越界替代下游 `Design/` 的高保真视觉设计：
- 统一采用中性灰阶线框与极少量功能语义色（主操作色、风险预警色、成功反馈色）；
- 必须填入真实业务文案、真实枚举标签及超长标题/多标签等贴近实战的模拟数据。

### 3.3 轨道一：功能空间多状态交互画板（`PROTO-PAGE-*`）规范与顶栏示意
每个画板对应 `06-pages/` 下的一个功能空间，**页面顶部必须固定挂载深灰底测试工作台（Workbench Bar）**，提供“子视图切换 + 状态枚举一键直达 + 视口断点切换 + 规格书回跳链接”：

```text
+---------------------------------------------------------------------------------------------------+
| [PROTO-PAGE-CHK]  视图:[主页面][优惠券抽屉] | 状态:[S1 正常态][S2 无地址态][S3 含失效商品] | 视口:[手机][平板][Web] | [查看规格书 ↗] |
+---------------------------------------------------------------------------------------------------+
|                                                                                                   |
|                        ( 下方按所选视口宽度与所选状态枚举，零前置操作立即渲染对应界面 )                     |
|                                                                                                   |
+---------------------------------------------------------------------------------------------------+
```
- **状态 1:1 咬合硬约束**：顶栏“状态”按钮组必须与对应 `PAGE-*` 规格书“第 4 节：页面级状态枚举表”中的 `S1 / S2 / S3 ...` **完全同名且数量一致**。

### 3.4 轨道二：跨空间状态传递微原型（`PROTO-FLOW-*`）规范与顶栏示意
仅针对**单张画板无法孤立呈现的跨页面状态传递、未登录操作挂起恢复、或配置修改后返回刷新**等关键跨页动线建立轻量沙盒：
1. **最小页面集裁剪**：每个沙盒仅纳入参与该条跨页状态传递的 2~3 个视图（例如“商品详情页 + 登录弹窗 + 确认订单页”），绝不混入无关模块。
2. **顶部实时上下文观测栏**：在顶栏实时透出当前沙盒的关键内存变量与“一键重置”按钮，让体验者直观看到每一步操作引起的状态跃迁：

```text
+---------------------------------------------------------------------------------------------------+
| [PROTO-FLOW-AUTH] 当前身份:未登录游客 | 本地已选规格:2件 | 挂起待恢复动作:立即购买 | [↺ 重置沙盒] [查看 FLOW 规格 ↗] |
+---------------------------------------------------------------------------------------------------+
```
