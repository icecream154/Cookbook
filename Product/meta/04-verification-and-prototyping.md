# 04. 结构化验收标准与双轨可交互微原型规范

本文档规定 `08-verification/` 层中**端到端验收用例集**（`AC-*`）与**可交互 HTML 微原型**（`PROTO-*`）的架构准则、粒度边界与实现规范。

---

## 1. 结构化验收标准（`acceptance-criteria.md`）编写规范

验收标准是连接产品规格与研发自测、QA 准出测试的契约底线：
1. **组织方式**：按核心业务能力模块分节，每条用例分配唯一编号 `AC-<CAP>-<NN>`。
2. **强制陈述格式**：统一采用三段式契约表格，必填列：
   `验收 ID | 关联规则/页面 (链接 RULE-*/PAGE-*) | 前置条件 (Given) | 触发动作 (When) | 预期确定性结果 (Then)`
3. **最低覆盖率红线**：
   - 每条核心端到端主干流程（`FLOW-*`）至少覆盖 1 条正向闭环验收用例；
   - 每条全局业务规则（`RULE-*`）的**临界数值边界**与**异常/空结果降级兜底（Fallback）分支**必须有独立验收用例覆盖；
   - 所有跨页面状态同步点（如 A 页修改配置影响 B 页展示、未登录拦截后状态接续）必须有专门验收用例覆盖。

---

## 2. 为什么严禁制作“大而全的单体可交互原型”？

在产品规格阶段，把整个应用做成单个包罗万象的 HTML/JS 单页应用（Monolithic Prototype）存在三大严重缺陷：
1. **边界状态极难触达**：评审者或设计师想查看某个深层异常态（如“检索零结果降级态”、“双端数据冲突弹窗”或“弱网加载失败态”），往往需要手动前置点击十余步构造条件，导致大量边缘状态在评审与视觉设计时被遗漏。
2. **职责边界失守**：单体原型为了跑通全局状态，不可避免在前端脚本里硬编码重写一套庞大的伪后端逻辑，极易与 `03-business-rules/` 的正式规则产生偏差。
3. **牵一发而动全身**：局部页面调整极易破坏其他模块的原型跳转，维护成本随迭代指数级上升。

因此，本元规范强制采用“**单页多状态交互画板 + 跨页状态传递微原型**”**双轨解耦架构**。

---

## 3. 双轨可交互 HTML 微原型架构规范

### 3.1 标准目录组织
```text
08-verification/prototypes/
├── index.html                       # 微原型导航总控台（汇总所有画板与动线入口，双向链接 Markdown 规格书）
├── shared/
│   ├── wireframe.css                # 跨原型共用的低保真中性灰线框样式库与多端视口容器壳样式
│   └── mock-data.js                 # 与 02 领域模型严格对齐的标准模拟数据集及核心纯函数规则演示器
├── pages/                           # 【轨道一】按 06 功能空间划分的单页多状态交互画板（PROTO-PAGE-*）
│   └── <space-name>.html
└── flows/                           # 【轨道二】聚焦关键跨页数据传递与拦截同步的微原型（PROTO-FLOW-*）
    └── <flow-name>.html
```

### 3.2 低保真视觉克制原则（Wireframe Fidelity Discipline）
产品规格中的 HTML 原型旨在验证**信息层级、区块组装、多端响应式排布、状态完备性与交互逻辑闭环**，严禁越俎代庖替代下游 `Design/` 的视觉设计：
- 统一使用中性灰阶与极少量功能语义色（主操作色、预警色、成功色）表达层级；
- 专注真实业务文案、真实枚举标签与真实极端数据长度测试，不引入未经设计系统定义的装饰性插画或花哨动效。

### 3.3 轨道一：功能空间多状态交互画板（`PROTO-PAGE-*`）强制规范
每个画板对应 `06-pages/` 下的一个功能空间（承载该空间的主页面及其专属抽屉/子弹窗），**页面顶部必须固定挂载灰底测试工作台（Workbench Bar）**，包含三项标准控件：
1. **子视图切换器**（若该空间含主页面 + 抽屉/子视图）：一键切换当前检视的目标 `PAGE-*`。
2. **页面状态一键直达按钮组（核心强制要求）**：按钮列表必须与对应 `PAGE-*` 文档“第 4 节：页面级状态枚举表”中的 `S1 / S2 / S3 ...` 状态编码 **1:1 同名对齐**。点击任一状态按钮，画布无需任何前置铺垫立即渲染该状态下的完整界面表现。
3. **多端视口宽度切换器**：支持一键切换手机竖屏、平板横屏、桌面宽屏等在 `SHELL-*` 中定义的容器壳形态，直观检验响应式分栏与抽屉变形逻辑。

### 3.4 轨道二：跨空间状态传递微原型（`PROTO-FLOW-*`）强制规范
仅针对**单页画板无法孤立表达的跨页面状态流转、权限拦截恢复或配置变更同步**（对应 `04-ia-and-flows/flows/` 中复杂度最高的跨页动线）建立独立沙盒：
1. **最小页面集裁剪**：每个动线微原型仅裁剪纳入参与该条状态传递的 2~3 个相关视图，绝不塞入无关模块。
2. **顶部实时状态观测栏**：在工作台顶栏实时外显当前沙盒的关键上下文变量（如登录身份、本地草稿值、云端档案值、挂起待恢复的动作队列）及“一键重置沙盒”按钮，让评审者清晰看懂每一步跨页状态流转的因果关系。
3. **双向可追溯链接**：所有微原型顶栏必须提供跳转回对应 Markdown 规格书（`PAGE-*` 或 `FLOW-*`）的相对链接；对应 Markdown 规格书元信息表也必须反向链接至该微原型文件。
