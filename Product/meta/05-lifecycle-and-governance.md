# 05. 活文档演进规程、新项目建库 SOP 与质量门禁清单

本文档定义**从零构建一套新产品规格库的标准作业程序（SOP）**、日常迭代中的**变更原地演进链路**，以及提交评审前的**质量门禁检查清单（Definition of Done）**。

---

## 1. 从零构建新产品规格库的七步标准 SOP

启动任意新产品项目时，严禁一上来直接画页面或写零散接口，必须严格按自顶向下依赖顺序推进：

1. **Step 1 确立愿景与能力边界（产出 `01`）**：梳理核心痛点，定义目标人群场景 `SCN-*`，划定当前纳入的能力版图 `FEAT-*`、非目标排除边界（Non-Goals）与多端/非功能约束 `NFR-*`。
2. **Step 2 划分数据子域并建模字典（产出 `02`）**：识别静态核心业务对象，按限界上下文拆分子目录，逐域定义术语 `TERM-*`、实体结构 `DOM-*` 与封闭枚举字典 `ENUM-*`，并在 `_index.md` 绘制全局 ER 关系图。
3. **Step 3 提炼跨领域业务规则（产出 `03`）**：将所有涉及推荐、匹配、计算、折算、权限同步、冲突裁决与空结果降级的逻辑，按业务决策能力簇编写为五要素规则卡 `RULE-*`。
4. **Step 4 搭建多端导航壳与端到端流程（产出 `04`）**：定义各视口断点下的导航容器壳 `SHELL-*`，按用户旅程阶段绘制标注了 `[PAGE-*]` 与 `[RULE-*]` 的跨页流程图 `FLOW-*` 及跨页状态同步表。
5. **Step 5 收口跨页公共组件与交互契约（产出 `05`）**：盘点在 `>= 2` 个页面复用的复合 UI 组件（`COMP-*`）及全局通用交互状态机（`PAT-*`），统一建模变体与契约。
6. **Step 6 组装单页规格与度量埋点（产出 `06` & `07`）**：按功能空间编写五段式单页规格书 `PAGE-*`（全部通过链接引用 `02/03/05`）；同步确立北极星与漏斗公式 `MET-*` 及事件字典 `EVT-*`，完成页面动作与埋点事件的双向绑定。
7. **Step 7 编写验收清单与双轨可交互微原型（产出 `08` + `spec/README.md`）**：编写覆盖全部规则边界的 `AC-*` 验收表，开发 1:1 对齐页面状态枚举的 `PROTO-PAGE-*` 画板与 `PROTO-FLOW-*` 跨页沙盒，最后完善项目级 `spec/README.md` 导读。

## 2. 存量产品迭代的“活文档原地演进”规程

当产品进入持续迭代期，遇到需求新增、修改或裁剪时，**严禁新建“V1.2 补充需求文档.md”**，必须按变更类型执行以下原地联动更新：

| 变更类型 | 标准原地更新传播路径 | 版本与兼容性注意事项 |
| :--- | :--- | :--- |
| **A. 拓展全新业务功能** | `01`（将事项从 Non-Goals 移入或新增 `FEAT-*`）→ `02`（增补实体/枚举）→ `03`（新增 `RULE-*`）→ `04/05`（增补流程与复用件）→ `06`（新增或扩充 `PAGE-*`）→ `07`（增补指标/事件）→ `08`（增补 `AC-*` 与原型状态） | 所有新增 ID 按该命名空间顺延递增编号，不改动既有条目的稳定 ID |
| **B. 调整既有计算/过滤规则** | 直接定位 `03` 对应 `RULE-*` 原地修改公式或决策矩阵 → 顺着该规则底部的“下游消费索引”核查 `04` 分支说明、`08` 验收用例期望值与 `mock-data.js` 演示逻辑 | 因 `06` 单页文档遵守“不抄公式只做引用”，通常无需改动 `06` 即可自动继承最新规则 |
| **C. 增删改枚举值或实体字段** | 直接修改 `02` 对应 `DOM-*` 或 `ENUM-*` → 全库全局搜索该锚点 ID，核查引用它的 `03` 判定矩阵、`05` 组件变体、`06` 数据绑定表及 `08` 线框原型标签 | 若涉及历史存量数据兼容，须在 `03` 同步补充旧枚举值的映射兜底规则 |
| **D. 下线废弃某项旧能力** | 从 `06/05/04/03` 移除失效页面与规则引用，或在 `01` 将该领域移入 Non-Goals；**已废弃的 ID 编号永久封存，严禁挪作新功能的编号复用** | 提交前必须运行全库链接扫描，确保无残留指向已删锚点的悬空断链 |

## 3. 提交评审前的质量门禁自检清单（Definition of Done）

每次完成建库或迭代更新后，必须逐项通过以下 6 项门禁校验方可定版交付：

- [ ] **门禁 1｜零断链与零悬空锚点**：全库所有 Markdown `[...](path#anchor)` 相对文件与 HTML `<a id="...">` 锚点、以及 HTML 原型内的 `href`/`src` 引用 100% 真实存在且可跳转。
- [ ] **门禁 2｜七条引用铁律全满足**：对照 [02-id-and-traceability.md 第 4 节](./02-id-and-traceability.md#rule-1)，确认无无源之水的功能、无私造字段的规则、无僵尸埋点、无漏测的规则降级分支。
- [ ] **门禁 3｜零越界重复抄写**：抽查 `06-pages/` 文档，确认其中未直接罗列枚举全集、未重写计算公式、未重复描述公共组件细节。
- [ ] **门禁 4｜原型状态与规格 1:1 咬合**：核对 `08` 各功能空间画板顶栏的状态切换按钮数量与编码，确认与对应 `06` 单页规格第 4 节状态表完全一致，且所有前端脚本无语法报错。
- [ ] **门禁 5｜完全自包含与时间无关性**：确认全库无残留会议过程代号（如“方案 B”、“方式 C”）、无未解释的缩写、无导致文档随迭代过期的“本次 MVP / 本期需求”阶段性措辞。
- [ ] **门禁 6｜Markdown 与图表渲染无误**：确认所有中英文混排 `**加粗**` 符合 CommonMark 边界规范，所有 Mermaid 代码块节点引号闭合无语法错误。
