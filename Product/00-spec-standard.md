# 00. 产品文档元规范（Specification Meta-Standard）

本文档定义 `Product/` 目录下所有产品规格资产的**职责边界、二级分包准则、全局语义化 ID 体系、结构化陈述模板与强制引用铁律**。任何新增或修改的产品文档必须严格遵守本规范。

---

## 1. 模块职责红线与二级分包标准

为防止信息跨文档重复抄写或职责腐化，每一层必须遵守单一职责边界与正交分类轴：

| 层级目录 | 允许承载的信息（职责内） | 严禁写入的信息（越界禁令） | 二级分类轴与分包公约 |
| :--- | :--- | :--- | :--- |
| `01-vision-and-scope.md` | 痛点背景、目标人群场景、MVP 功能范围、全局非功能约束 | 具体字段枚举、算法公式、页面区块布局 | 单文件全局统领 |
| `02-domain-model/` | 领域术语定义、静态业务实体字段契约、全局标准枚举值 | 动态计算规则、UI 控件形态、交互提示语 | **按限界上下文（业务子域）分包**；每域拆分为 `terms.md`、`entities.md`、`enums.md` |
| `03-business-rules/` | 跨领域判定矩阵、配餐/换算/检索/同步算法与降级兜底规则 | 页面按钮摆位、弹窗视觉形态 | **按核心业务决策能力簇分文件**；由 `_index.md` 统一注册 |
| `04-ia-and-flows/` | 全局页面拓扑、多端响应式容器壳、跨页任务流与跨页同步关系 | 单页内部表单项校验、公共组件局部细节 | 架构壳独立；流程在 `flows/` 下**按用户价值旅程阶段分文件** |
| `05-components-and-patterns/` | 在 `>= 2` 个页面复用的业务组件变体、全局通用交互状态契约 | 仅单一页面私有的局部布局与一次性逻辑 | 拆分为 `shared-components.md` 与 `interaction-patterns.md` |
| `06-pages/` | 单页/子抽屉的元信息、三端区块排布、状态枚举、事件绑定表 | 重写枚举全集、重写计算公式、重写公共组件逻辑 | **按 IA 功能空间分文件夹**；主页面与专属子抽屉拆分为同级小文件 |
| `07-metrics-and-tracking/` | 北极星指标、转化漏斗计算公式、关键业务事件及上报业务属性 | 无指标消费的细碎 UI 曝光埋点、底层 SDK 代码细节 | 拆分为 `metrics-funnel.md` 与 `event-dictionary.md` |
| `08-verification/` | `Given-When-Then` 验收清单、单页多状态画板 HTML、跨页动线微原型 HTML | 单体大而全前端应用代码、规格书未定义的野生功能 | 集中收口于 `prototypes/`，共用 `shared/` 线框样式与模拟数据集 |

> **`_index.md` 强制公约**：凡包含多个业务文档的目录（`02`、`03`、`04/flows`、`05`、`06`），根部必须提供 `_index.md`，声明本目录的分包判据及本层全部 ID 的注册导航表。

## 2. 全局语义化 ID 编码规范

所有核心规格条目必须分配**全局唯一、语义自解释、插页不断号**的标识符，并在标题旁附带显式 HTML 锚点 `<a id="xxx"></a>`（全小写连字符格式），确保跨文件精准跳转：

| 条目类型 | ID 格式规范 | 锚点示例 | 示例含义 |
| :--- | :--- | :--- | :--- |
| 用户场景 | `SCN-<两位序号>` | `#scn-01` | `SCN-01` 独居快手一碗端与清冰箱场景 |
| 功能范围 | `FEAT-<两位序号>` | `#feat-02` | `FEAT-02` 个性化今日三餐智能配餐与换菜 |
| 非功能约束 | `NFR-<两位序号>` | `#nfr-01` | `NFR-01` Mobile-First 三端响应式一致性 |
| 领域术语 | `TERM-<子域缩写>-<序号>` | `#term-rcp-01` | `TERM-RCP-01` 标准食材库（`USR`用户/`RCP`菜谱/`PLN`规划） |
| 领域实体 | `DOM-<子域缩写>-<PascalName>` | `#dom-rcp-recipe` | `DOM-RCP-Recipe` 菜谱核心聚合实体 |
| 标准枚举 | `ENUM-<子域缩写>-<PascalName>` | `#enum-rcp-spiciness` | `ENUM-RCP-Spiciness` 菜谱与偏好通用辣度枚举 |
| 业务规则 | `RULE-<能力簇缩写>-<序号>` | `#rule-cook-02` | `RULE-COOK-02` 多量纲食材人性化取整换算规则 |
| 视口容器壳 | `SHELL-<Breakpoint>` | `#shell-tablet` | `SHELL-Tablet` 平板端厨房横屏双栏导航壳 |
| 业务流程 | `FLOW-<旅程缩写>-<序号>` | `#flow-auth-02` | `FLOW-AUTH-02` 受限动作拦截登录接续与档案合并流 |
| 公共组件 | `COMP-<PascalName>` | `#comp-recipecard` | `COMP-RecipeCard` 跨页复用菜谱摘要卡片 |
| 交互模式 | `PAT-<PascalName>` | `#pat-authresume` | `PAT-AuthResume` 受限操作登录自动接续模式 |
| 页面/子视图 | `PAGE-<空间缩写>-<序号>` | `#page-plan-01` | `PAGE-PLAN-01` 今日菜谱主页 |
| 业务指标 | `MET-<NSM或两位序号>` | `#met-02` | `MET-02` 今日三餐推荐采纳与换菜效率指标组 |
| 关键事件 | `EVT-<两位序号>` | `#evt-05` | `EVT-05` 触发单菜或整餐换一换事件 |
| 验收用例 | `AC-<能力缩写>-<序号>` | `#ac-cook-02` | `AC-COOK-02` 自然计数食材禁止出现反直觉小数验收 |
| 交互微原型 | `PROTO-<PAGE或FLOW>-<缩写>` | — | `PROTO-PAGE-COOK` 菜谱详情与跟做空间状态画板原型 |

## 3. 各类信息的强制陈述模板（禁止大段模糊散文）

### 3.1 领域实体与枚举陈述规范（用于 `02-domain-model/`）
- **实体表必填列**：`字段标识 | 中文名称 | 类型 | 必填 | 取值约束 / 关联枚举(链接) | 业务语义说明`
- **枚举表必填列**：`枚举编码(Code) | 标准展示文案(Label) | 排序/数值权重 | 业务判定语义`

### 3.2 业务规则五要素卡片规范（用于 `03-business-rules/`）
每条 `RULE-*` 必须包含以下固定结构，超过 2 个条件组合的分支必须使用**决策矩阵表**：
1. **触发时机与适用范围**
2. **输入依赖契约**（必须显式链接至 `DOM-*` / `ENUM-*`）
3. **核心判定矩阵 / 计算公式**
4. **边界与降级兜底（Fallback）**
5. **下游消费索引**（列出引用本规则的 `FLOW-*` / `PAGE-*`）

### 3.3 单页规格五段式规范（用于 `06-pages/`）
每份 `PAGE-*` 文档严格由以下 5 节构成：
1. **页面元信息表**：`PAGE-ID`、载体形态（一级页/二级页/底部或侧滑抽屉/全屏覆盖层）、访问权限、上游入口、下游出口、关联微原型链接。
2. **三端响应式区块布局表**：引用 `SHELL-*` 说明在 Mobile / Tablet / Web 下的区块排列差异。
3. **区块组装与数据绑定表**：`区块ID | 区块名称 | 复用组件(COMP-*)或原子控件 | 绑定实体字段(DOM-*) | 显隐条件`。
4. **页面级状态枚举表**：穷举 `S1 默认正常态 / S2 游客或特例态 / S3 空数据态 / S4 异常或降级态`（**必须与对应单页 HTML 原型顶部的状态切换器 1:1 严格同名对齐**）。
5. **交互事件映射表**：`用户动作(When) | 前置校验/模式(PAT-*) | 执行业务规则(RULE-*) | 界面状态变化或跳转(Then) | 上报事件(EVT-*)`。

## 4. 跨文档引用语法与 7 条强制依赖铁律

### 4.1 标准引用语法
统一使用 **Markdown 相对路径 + 锚点链接**，以条目 ID 作为链接文本前缀（示例以从 `06-pages/<space>/xxx.md` 引用为例，在当前根级文档实际链接如下）：
- 引用枚举：[ENUM-RCP-Spiciness](./02-domain-model/recipe-catalog/enums.md#enum-rcp-spiciness)
- 引用规则：[RULE-COOK-02](./03-business-rules/portion-and-cooking.md#rule-cook-02)
- 引用组件：[COMP-RecipeCard](./05-components-and-patterns/shared-components.md#comp-recipecard)

### 4.2 七条强制依赖校验铁律（Spec Integrity Rules）
1. **功能必有场景源头**：任意 `FEAT-*` 必须至少引用 1 个 `SCN-*`；无场景支撑的功能不得纳入范围。
2. **规则严禁私造字段**：任意 `RULE-*` 的输入参数与枚举判定值必须链接至 `02-domain-model/` 中已注册的 `DOM-*` / `ENUM-*`。
3. **流程节点必有归属**：任意 `FLOW-*` 流程图中的页面节点必须标注 `[PAGE-*]`，关键分支菱形必须标注判据 `[RULE-*]` 或 `[PAT-*]`。
4. **单页规格零冗余组装**：`PAGE-*` 严禁抄写枚举值列表、严禁重写规则算法公式、严禁重复描述公共组件与登录接续细节，一律通过 ID 链接引用。
5. **指标与事件双向闭环**：任意 `MET-*` 指标公式的分子/分母必须由 `EVT-*` 导出；任意 `EVT-*` 必须绑定触发位置（`PAGE-*` / `COMP-*`）且至少服务于 1 个 `MET-*`。
6. **画板原型与页面状态 1:1 咬合**：`08` 中的单页画板原型 `PROTO-PAGE-*` 顶栏状态按钮必须完整覆盖对应 `PAGE-*` 第 4 节定义的全部状态枚举；跨页动线原型 `PROTO-FLOW-*` 必须覆盖对应 `FLOW-*` 的全部分支。
7. **规则边界必有验收覆盖**：每条 `RULE-*` 的正常逻辑与降级兜底（Fallback）分支，在 `08-verification/acceptance-criteria.md` 中必须有至少 1 条 `AC-*` 显式验证。
