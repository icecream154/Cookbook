# 01. 产品愿景、用户场景与功能范围（Vision, Personas & Scope）

## 1. 产品背景与核心价值主张

### 1.1 核心问题域
居家做饭用户在日常饮食决策与下厨执行中长期存在四处体验断层：
1. **每日决策过载**：“今天早中晚吃什么？”缺乏结合用餐人数、个人忌口、厨具条件与健康目标的成套方案。
2. **家庭规模错配**：传统菜谱固定按 2~3 人份编写，1 人独居易剩菜且洗碗负担重，多口之家又需自行拼凑荤素汤羹与心算调料倍数。
3. **复杂找菜低效**：面对“清冰箱现有多种食材 + 避开过敏忌口 + 限定微辣快手 + 只在自己收藏里挑”的复合诉求，单一关键词搜索无法胜任。
4. **厨房实操割裂**：做菜时双手沾水油，上下翻找食材克数与长文步骤极易手忙脚乱，火候转换与营养构成缺乏可视化指引。

### 1.2 一句话产品定位
一款 **Mobile-First、全端自适应（手机 / 平板 / Web）的个性化三餐规划与结构化多媒体菜谱应用**，打通“饮食画像建档 → 每日按人数智能配餐 → 多维正反食材检索 → 动态折算与大屏跟做”完整下厨闭环。

### 3.2 当前产品非目标边界（Non-Goals / Out-of-Scope）

以下领域不在当前产品能力边界内，以确保核心配餐与下厨体验的专注度。未来随产品演进若决定拓展某项能力，须先将其从本节移入 `3.1` 分配 `FEAT-*` 编号，再向下游 `02` ~ `08` 各层增量展开：

- **UGC 社区与社交**：不支持用户上传/编辑自建菜谱、评论区盖楼、点赞关注动态流（当前采用高质量结构化官方精编菜谱库 PGC）。
- **生鲜履约交易**：不接入第三方买菜平台购物车结算与骑手配送。
- **重硬件外设联动**：不支持拍照估算食物热量或蓝牙控制智能烤箱/料理机。

## 4. 全局非功能性体验约束（`NFR-*`）

| 约束 ID | 约束维度 | 规格要求 |
| :--- | :--- | :--- |
| <a id="nfr-01"></a>**NFR-01** | **Mobile-First 全端响应式一致性** | 以手机竖屏（`< 768px`）为首要设计基准，同时无缝适配平板厨房横屏分栏（`768px ~ 1023px`）与桌面 Web 宽屏常驻筛选布局（`>= 1024px`），三端共享 100% 相同的业务规则与数据契约（详见 [04-1 全局信息架构与多端容器壳](./04-ia-and-flows/ia-and-shell.md)）。 |
